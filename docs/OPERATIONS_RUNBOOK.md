# Operations runbook

Use `npm run stack:start`, `stack:stop`, `stack:restart`, `stack:status`, `stack:logs`, and `stack:verify` for the local stack. The n8n volume is persistent; back it up only while stopped and preserve the existing `N8N_ENCRYPTION_KEY` when restoring. In the Compose stack, n8n uses `http://app:3000`; use `http://host.docker.internal:3000` only when n8n runs separately from the app container.

`Remote Role Acquisition Engine` is the sole canonical n8n workflow. Its single inactive canvas has six entry points: daily acquisition at 5:00 PM Asia/Kolkata, 15-minute guarded delivery polling, 15-minute inbox monitoring, hourly follow-up eligibility, hourly operations, and a manual controlled self-test. The daily branch calls guarded application APIs for ingestion, incremental qualification/ranking, bounded contact discovery, and gated drafting; it never sends Gmail. Delivery, inbox, and follow-up branches remain independently triggered on the same canvas and never decide eligibility or send safety.

Credential assignment matrix: every internal HTTP node uses `Remote Role Engine — Internal API` Header Auth with the header name `X-Internal-Automation-Token`. Gmail nodes in delivery, inbox monitoring, and self-test use the owner-assigned `Gmail Outreach — Dedicated` credential. No credential IDs or secret values belong in workflow JSON.

Use `/api/health` and n8n `/healthz` for health checks. Reconnect Gmail OAuth only through n8n’s owner-managed UI. For Gemini/provider failures, inspect aggregate assessment categories and rerun the bounded resumable backfill; do not print provider payloads. For Supabase failures, keep autosend disabled and restore only after read/write health checks pass.

Recover stale locks only after confirming no assessment process is running. The emergency kill switch is `AUTOSEND_ENABLED=false` plus pausing the unified workflow. Rotate the internal token manually in runtime configuration and the single Header Auth credential together. A sleeping/offline desktop cannot run scheduled work; due follow-ups are rechecked after recovery, without duplicate claims. Review `npm run verify:unified-n8n`, `npm run verify:end-to-end`, and operations status daily, and back up n8n weekly.
